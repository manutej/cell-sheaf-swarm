Unified integration ideation

Ranked survivors from 28 raw candidates (21 rejected). Grounded in README split, swarm.sheaf.json trunk specimen, store.ts clock law, and contract validation CI.

Grounding context

  • /agent is a thin workspace folder containing only repos/cell-sheaf and repos/cell-sheaf-swarm — not a monorepo, no shared package manager or orchestration yet.
  • cell-sheaf-swarm is the published kernel: SheafGraph schema, ROLL law, validate script + CI, TypeScript types/load/insight/store, React observatory components, extra contracts (adp.sheaf.json, ROLL.md, schema).
  • cell-sheaf is the HTML design template + GitHub Pages surface; README explicitly points kernel readers to swarm. Contracts largely mirror swarm but catalog lacks adp; no TS, no CI, no schema file. Adds data/trunk-sheaf.json.
  • Shared metaphor: JSON sheaf is source of truth; restriction status is glue; gold (onTrunk) is earned; operad node q0 asks compose ≟ collapse; agents pulse on ρ with block/commit semantics in pulse().
  • Integration pain already modeled: broken orchestr → lattice-ops, strange feeds, missing trunk→wiki — the specimen is a map of real federation blockers.

Topic axes

  1. Contract authority & repo sync boundaries
  2. Federated runtime / agent loop orchestration
  3. Evaluation, learning, and operad gates
  4. Presentation parity (static HTML vs React observatory)
  5. Workspace packaging (/agent as integration layer)

Ranked ideas

Axis 1 · Rank 1 · Confidence 88% · Complexity Medium

1. Formalize kernel + surface split (release-synced sisters)

Description: Treat cell-sheaf-swarm as the single authority for contracts/, schema, validate, and TS kernel; cell-sheaf as a downstream mirror of template/ + catalog subset for Pages-only consumers. Automate sync on semver tags (copy contracts + template, run validate in both).

Basis: direct: cell-sheaf README line 7 — “Kernel + swarm clock + contract schema: manutej/cell-sheaf-swarm”. direct: swarm README line 9 — “Sister surface: manutej/cell-sheaf”.

Rationale: Matches author intent; removes drift (catalog, ROLL.md, adp specimen, tokens.css diff) without forcing a monorepo.

Downsides: Two repos forever; sync automation must be maintained; contributors need a clear “edit here first” rule.

Axis 2 · Rank 2 · Confidence 82% · Complexity High

2. Headless federated pulse runner (CLI)

Description: Extract pulse() clock law from Zustand into a Node CLI that reads a sheaf JSON, emits events, and dispatches work to pluggable backends (local shell, GitHub Actions matrix job, Cursor cloud agent webhook) keyed by agent role and edgeId.

Basis: direct: store.ts documents “Clock law: idle → launch → residual on ρ → commit or block”. direct: swarm specimen lists orchestrator, eval, lattice-ops pillars as separate “folders”.

Rationale: Turns decorative simulation into federated MVP without rewriting the visual layer first.

Downsides: Backend adapters are real engineering; security for remote dispatch; must not violate “no shared mutable” law in operad prompts.

Axis 3 · Rank 3 · Confidence 85% · Complexity Medium

3. Evaluation harness v0 (four seats → structured findings)

Description: Promote EVAL.md adversarial seats (user, operator, craft, red) into first-class findings[] on the sheaf with severities; wire reviewer agents in pulse() to increment JEV and attach seat verdicts; validate with schema + golden fixture tests.

Basis: direct: identical EVAL.md in both repos. direct: swarm.sheaf.json operad q1 JEV battery and eval pillar folder multi-agent-eval.

Rationale: Learning loop closes when eval outputs propose ρ status patches humans accept.

Downsides: Risk of theater if findings are not tied to executable checks; needs human-in-loop for strange ρ.

Axis 1 · Rank 4 · Confidence 80% · Complexity Low

4. Contract release bus (validate-as-integration-boundary)

Description: Single CI truth: swarm validates on push; cell-sheaf CI (add workflow) checks out pinned swarm tag or submodule SHA and runs the same validate-sheaf.mjs. PRs that change contracts without green validate cannot merge.

Basis: direct: swarm has .github/workflows/sheaf.yml; cell-sheaf has none. direct: catalog drift (adp missing in cell-sheaf).

Rationale: Cheapest integration proof before runtime federation.

Downsides: Does not run agents; only guards JSON glue.

Axis 3 · Rank 5 · Confidence 72% · Complexity Medium

5. Operad q0 as merge / deploy gate

Description: Map operad compose/collapse/oc fields to CI checks: composed partial artifacts (JEV, GNOCIS, glue lint) must match collapsed trunk verdict before a restriction flips to ok or a release tag ships.

Basis: direct: operad node q0 question in swarm.sheaf.json. reasoned: aligns “gold is earned” with automation rather than visual-only gold.

Rationale: Gives a crisp MVP definition of “trunk closed.”

Downsides: Requires measurable compose/collapse functions; easy to over-formalize early.

Axis 4 · Rank 6 · Confidence 78% · Complexity Medium

6. Insight parity — port repair ranking to volume.boot.js

Description: Share one repair/verdict algorithm: either bundle insight.ts via esbuild for the static template or duplicate minimally with shared test vectors from validate tests.

Basis: direct: EVAL.md “verdict is single-fix counterfactual” matches insight.ts repair ranking. HTML views still use instrument names per EVAL critique.

Rationale: Integrated product feels one-minded in browser and observatory.

Downsides: JS bundle size; temptation to fork tokens.css — forbidden by ROLL law.

Axis 5 · Rank 7 · Confidence 75% · Complexity Low

7. /agent meta-orchestrator (pinned twin repos)

Description: Add /agent/README.md, manifest.json pinning both SHAs, and docs/plans — workspace for Cloud Agent runs without merging git histories.

Basis: direct: /agent contains only repos/* checkouts today.

Rationale: Matches how this integration task was invoked; low risk entry to federated docs and cross-repo PRs.

Downsides: Not a substitute for package publishing; may confuse if treated as third product repo.
